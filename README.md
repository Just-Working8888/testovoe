# HTTP speedtest

Консольный скрипт, который замеряет скорость HTTP-загрузки конкретного ресурса.
Он делает **10 последовательных GET-запросов** к указанному URL, каждый раз дожидается
полного получения тела ответа и выводит среднее время запроса, общий объём скачанных
данных и среднюю скорость.

## Требования

- Python 3.11+ (код совместим и с 3.9+, тесты прогонялись на 3.9.6).
- Внешних зависимостей нет, используется только стандартная библиотека (`urllib`, `argparse`, `unittest`).

## Запуск

```bash
python3 speedtest.py <URL>
```

Пример:

```bash
python3 speedtest.py https://proof.ovh.net/files/1Mb.dat
```

URL с `?` и `&` берите в кавычки, иначе их перехватит shell:

```bash
python3 speedtest.py 'http://speed.cloudflare.com/__down?bytes=5000000'
```

Коды завершения:
- `0`: была хотя бы одна успешная попытка;
- `1`: все 10 попыток неуспешны;
- `2`: некорректные аргументы, например URL без схемы `http://`/`https://`;
- `130`: прервано через Ctrl+C.

## Как считается скорость

- Время попытки измеряется через `time.perf_counter()`: от момента непосредственно перед
  запросом до получения последнего байта тела. Сюда входят DNS, TCP/TLS-рукопожатие,
  ожидание первого байта и сама передача.
- Объём считается по **фактически полученным байтам тела**, а не по заголовку `Content-Length`.
  Если сервер прислал `Content-Length`, но соединение оборвалось раньше, попытка считается
  неуспешной.
- В расчёт попадают только успешные попытки (HTTP 2xx, тело получено полностью).

```
среднее время = сумма времени успешных попыток / число успешных попыток
скорость      = сумма байт успешных попыток / сумма времени успешных попыток
```

Скорость считается по суммам, а не как среднее скоростей отдельных попыток: так каждая
попытка входит в итог с весом, пропорциональным своему вкладу.

## Единицы измерения

| Единица | Формула | Что означает |
|---|---|---|
| **MiB/s** | `байты / секунды / 1 048 576` | мебибайты в секунду (двоичная, 1 MiB = 2²⁰ байт), в таких единицах обычно показывают размеры файлов |
| **Mbps** | `байты × 8 / секунды / 1 000 000` | мегабиты в секунду (десятичная), в таких единицах провайдеры указывают тарифы |

1 MiB/s ≈ 8.39 Mbps. Объём выводится в MiB и в байтах.

## Тесты

```bash
python3 -m unittest -v
```

Тесты поднимают локальный HTTP-сервер на `127.0.0.1` и не обращаются к внешним сервисам.
Что проверяется:
- расчёт среднего времени и скорости (MiB/s и Mbps), исключение неуспешных попыток;
- полностью неуспешный прогон: нет деления на ноль, код завершения `1`;
- частично успешный прогон (чередование 500/200);
- точный подсчёт байт: с `Content-Length`, без него и с `Transfer-Encoding: chunked`;
- строгая последовательность: сервер ни разу не видит двух одновременных запросов,
  ровно 10 попыток без автоповторов;
- таймаут сокета, общий лимит на попытку, оборванное тело, отказ в соединении, некорректный URL.

## Обработка ошибок

Каждая из 10 попыток независима: при ошибке выводится понятное сообщение, и скрипт
переходит к следующей попытке. Автоматических повторов нет.

- **HTTP 4xx/5xx**: попытка неуспешна, статус выводится.
- **Таймауты.** Таймаут 10 с действует на подключение и на каждое чтение из сокета.
  Дополнительно действует общий лимит 120 с на попытку, чтобы сервер, отдающий данные
  по байту, не держал скрипт бесконечно.
- **Сетевые ошибки** (DNS, отказ в соединении, разрыв, ошибка SSL): сообщение с причиной.
  Проверка SSL-сертификатов **не отключается**.
- **Неожиданные ответы**: тело короче заявленного `Content-Length`, ошибки протокола.
- **Некорректный URL** (без схемы, не http/https, без хоста) отклоняется на этапе
  разбора аргументов (код `2`).

Скрипт отправляет заголовки `Cache-Control: no-cache` и свой `User-Agent`: некоторые
CDN отвечают 403 на стандартный `Python-urllib`. Редиректы `urllib` выполняет автоматически.

## Ограничения

Скрипт измеряет скорость HTTP-загрузки **конкретного ресурса с конкретного сервера**,
а не максимальную скорость интернет-подключения. На результат влияют удалённость и
загрузка сервера, CDN-кэш, TCP slow start (на маленьких файлах он заметно занижает
скорость, поэтому лучше брать ресурсы от нескольких мегабайт) и то, что каждая попытка
открывает новое соединение и заново проходит DNS/TLS. Это сделано намеренно: каждый
запрос измеряется «с нуля».
